ООП — программа из объектов 🧩

объект = данные + действиячто он знает + что он умеет
hero.hpсвойство — данные объекта
hero.shout()метод — функция внутри объекта

В уроках 2–3 данные жили отдельно, а функции получали их параметром: getTotal(cart). ООП — объектно-ориентированное программирование: данные и действия живут вместе, в объекте. Последняя строка кода — проблема, которую решает класс.

Все три принципа работают через классы — с них и начинаем

Обзор на 3 минуты, без кода. Инкапсуляцию сегодня сделаем руками (# и get/set), наследование и полиморфизм — на уроке 5 вместе с prototype и исключениями.

Класс — формочка, объект — печенька 🍪

class Hero {
  constructor(name, power) {
    this.name = name;
    this.power = power;
    this.hp = 100;
  }
  info() {
    return `${this.name} ❤️${this.hp}`;
  }
  attack(enemy) {
    enemy.hp -= this.power;
  }
}

// формочка одна — печенек сколько угодно

Создайте 3–4 героя с разными именами — у всех одинаковое устройство (name, power, hp), но свои значения. Клик по печеньке — info(): у каждой отвечает своё this. Кнопка attack: h1 бьёт h2 — меняется hp именно у h2. Класс — чертёж, сам по себе он ничего не делает; new — включает станок.

class · constructor · new

class Hero { … }чертёж; имя — с большой буквы
constructor(name, power)запускается сам при new — собирает объект
this.name = nameзаписать свойство в новый объект
new Hero('Аня', 12)создать объект по чертежу
anya instanceof Heroсделан по этому классу? true / false
Порядок при new: создаётся пустой объект → запускается constructor, внутри него this — этот новый объект → объект возвращается. Консоль пишет Hero { … } — по какому чертежу сделан объект. Попросите добавить третьего героя прямо в коде.

Анатомия класса

class Hero {
  constructor(name) {
    this.name = name;
  }
  info() {
    return `Я ${this.name}`;
  }
}
const anya = new Hero('Аня');
Части подсвечиваются по очереди сами, можно кликать по легенде. Обратите внимание: между методами класса НЕ ставят запятые — в отличие от объекта-литерала.

this — «я сам» 🙋

anya.info()this — объект СЛЕВА от точки: anya
this.hp -= damageметод меняет СВОИ свойства
return this.info()метод вызывает другой метод
enemy.hpчужой объект — приходит параметром
Правило одной строки: this — то, что слева от точки в момент вызова. Метод info один на всех, а отвечает каждый за себя. Без this внутри метода JS ищет обычную переменную — это следующий квиз.

Квиз · забыли new

▶ Старт — таймер, G — следующий шаг. Класс без new вызвать нельзя: TypeError: Class constructor Cat cannot be invoked without 'new'. Это самая частая ошибка шага 1 практики.

Квиз · забыли this

nick — параметр КОНСТРУКТОРА, в методе hi его не видно. JS ищет переменную nick — её нет → ReferenceError: nick is not defined. Нужно this.nick. Покажите на слайде this: свойства объекта всегда через this.

Свойства и методы 🧰

grades = [];поле класса: свойство без конструктора
addGrade(g) { … }метод: без слова function и без запятых
murad.gradesу каждого объекта — свои данные
a.average === b.averageа метод один на всех → true
Поле класса (grades = []) — то же, что this.grades = [] в конструкторе, только короче; удобно для начальных значений. В консоли видно: поля появляются раньше свойств из конструктора. Методы лежат в классе один раз и общие для всех объектов — данные у каждого свои.

Квиз · два объекта

Две печеньки из одной формочки — всё равно две разные печеньки. Объекты сравниваются по ссылке (урок 3), а не по содержимому → false.

static — свойство класса ⚡

Math.random()вы уже знаете static: метод самого Math
static count = 0;одно значение на весь класс
Hero.count++обращаемся через имя класса
static random(name) { … }метод класса: Hero.random('Бот')
anya.countу объекта статики нет → undefined
Обычный метод отвечает за ОДИН объект (this — этот герой). Статический — за весь класс: счётчик, фабрика, сравнение двух объектов. Math.random, Array.isArray, Number.isInteger — всё это static, вы пользовались ими весь урок 3. Запустите 2–3 раза — сила бота каждый раз новая.

Квиз · static у объекта

static живёт в самом классе, а не в объектах: h.max → undefined, Hero.max → 100.

Инкапсуляция: # 🔒

#money = 0;приватное поле: видно только внутри класса
this.#money += sumвнутри методов — можно
w.#moneyснаружи — SyntaxError, код не запустится
if (sum <= 0) return '❌ …'метод-охранник проверяет, что пускать
Инкапсуляция — первый принцип ООП: внутренности спрятаны, менять их можно только через методы, а методы проверяют входные данные. Покажите: раскомментируйте последнюю строку и запустите — SyntaxError, весь код не выполнится. Иногда в чужом коде встречается _money — это просто договорённость «не трогай», защиты она не даёт.

Геттеры и сеттеры 🎛️

get temp() { return … }читается как свойство: t.temp — без ()
set temp(value) { … }срабатывает при t.temp = 50
Math.min(30, Math.max(10, v))сеттер-охранник: держит 10…30
get mood()вычисляемое свойство: только чтение
Геттер и сеттер — окошки к приватному полю: снаружи выглядит как обычное свойство t.temp, а внутри работает код. Math.min(30, Math.max(10, v)) читается изнутри: не ниже 10, потом не выше 30 — ровно это понадобится в шаге 4 практики (0…100). Ловушка: в сеттере писать this.#temp, а не this.temp — иначе сеттер вызовет сам себя бесконечно.

Квиз · геттер со скобками

u.full — уже строка 'Аня Алиева' (геттер сработал при чтении). Строку вызвать нельзя: TypeError: u.full is not a function. Геттер читают БЕЗ скобок.

Квиз · сеттер-охранник

b.n = 25 вызывает сеттер, он пропускает не больше 10 → 10. Ровно так в практике hp не уйдёт ниже 0 и выше 100.
