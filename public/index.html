Прототип — общие умения

У двух героев разные имена, но инструкция «как представиться» одна на всех.

Вместо копии метода у каждого объекта — общий метод в прототипе. Если своего свойства нет, JavaScript ищет его дальше по цепочке.

Имя своё. Метод общий.
Сначала обсудите картинку и бытовой пример без кода. Попросите одного студента пересказать идею своими словами. На следующем слайде связываем пример с JavaScript. Не добавляйте отдельное время: вступление входит в минуты темы.

prototype: сначала через функцию 🧩

function Hero(name) { this.name = name; }Функция-конструктор: используем с new.
new Hero('Аня')Создаём объект со своим полем name.
Hero.prototype.info = function () { … }Один общий метод для всех героев.
anya.info()Ищем метод у объекта, затем в его прототипе.
Пишем по четырём этапам. После каждого запускаем текущий код. На этапе объявления метода консоль может не измениться — это ожидаемо. Данные (name) лежат в каждом объекте, а методы — один раз в Hero.prototype. Объект «не знает» info сам, он спрашивает у прототипа. Зачем: экономия памяти и общий код для всех объектов. Массивы, строки, даты устроены так же: push лежит в Array.prototype.

Наследование в JS — это и есть цепочка прототипов.

class — удобная запись

Одного и того же героя можно описать функцией-конструктором или классом.

В обоих вариантах объект хранит имя, а общий метод находится в prototype. В class конструктор и методы собраны в одной понятной записи.

Теперь то же самое через class 🧬

function Hero(name) ↔ constructor(name)Сохраняют name в создаваемом объекте.
Hero.prototype.info = function () { … }Так записали общий метод через функцию.

Пишем по четырём этапам. После каждого запускаем текущий код. На этапе объявления метода консоль может не измениться — это ожидаемо. Под капотом class делает ровно то же: кладёт методы в prototype. Старую запись встретите в чужом коде и в старых учебниках — важно её узнавать. Писать будем через class. Встроенные прототипы (Array, String) не трогаем: сломаете чужой код.

extends и super() 🧬

class Mage extends HeroMage получает ВСЁ, что умеет Hero
super(name, power)вызвать конструктор родителя — первой строкой!
this.mana = manaдобавить своё — только после super

Наследование — второй принцип ООП: общий код в родителе, особенности — в детях. super(...) — это «конструктор родителя, сделай свою часть». Пока super не вызван, this использовать нельзя — это следующий квиз.

Переопределение — своя версия

Обычный герой сообщает имя и силу. Маг представляется так же, но ещё сообщает запас маны.

Пишем у мага метод с тем же именем. Через super.info() получаем результат родителя и дополняем его.

Переопределение и super.метод() ✏️

info() { … }в ребёнке — метод с тем же именем
super.info()вызвать версию родителя и дополнить

Переопределение — ребёнок говорит «я делаю это по-своему». super.info() — не копировать код родителя, а взять его результат и добавить своё (🔮). Вспомните демо «цепочка»: info нашёлся в Mage.prototype раньше, чем в Hero.prototype.

Квиз · забыли super

В конструкторе ребёнка this появляется только после super(...). Без него — ReferenceError: Must call super constructor before accessing 'this'. Самая частая ошибка шага 1 практики.

Квиз · instanceof

Каждый B — это A (маг — тоже герой) → true. Но не каждый A — это B (не каждый герой маг) → false.

Полиморфизм — одна команда

Говорим «Подай голос» коту и собаке. Кот отвечает «Мяу», собака — «Гав».

Команда одна, но каждый объект выполняет её по-своему. В коде вызываем один метод, а нужная реализация выбирается у конкретного объекта.

Один вызов. Разное поведение.

Полиморфизм 🎭

speak()Одна команда для всех животных.
this.voice()Каждое животное отвечает своим голосом.
for (const animal of zoo)В цикле не нужно проверять класс.
Пишем по четырём этапам. После каждого запускаем текущий код. На этапе объявления метода консоль может не измениться — это ожидаемо. Полиморфизм — третий принцип ООП: «много форм» одного вызова. Цикл не знает, кто перед ним, и не проверяет тип — просто зовёт speak(), а speak зовёт this.voice(), и у каждого животного находится свой. Fish не переопределила voice — сработал родительский '...'. Исключение — действие не удалось

Хотим прочитать имя пользователя, а самого пользователя нет. Продолжить это действие нельзя.

JavaScript сообщает об ошибке и прерывает текущий путь. В catch мы можем обработать проблему и продолжить программу.

Ошибка → обработка → продолжаем.

Исключения: try / catch 🛟

исключениеошибка во время работы: программа падает
try { … }«попробуй» — опасный код здесь
catch (e) { … }ошибка поймана, программа живёт дальше
e.name · e.messageтип ошибки и её текст
Исключительная ситуация — то, что может пойти не так во время работы: нет данных, неверный ввод, сервер не ответил. Покажите: удалите try и catch и запустите — красная ошибка, последняя строка не выполнилась. С try программа ловит ошибку и продолжает.
Сначала — смысл

throw и finally — сообщить и завершить

В лавке не хватает золота: продавец объясняет причину отказа. В конце он закрывает лавку при любом исходе.

throw сообщает, почему действие невозможно. catch обрабатывает ошибку. finally выполняет завершающее действие и при успехе, и после обработки ошибки.

Завершение нужно в обоих случаях.

throw и finally 🎯

throw new Error('текст')бросить СВОЮ ошибку, если данные плохие
finally { … }выполнится всегда: была ошибка или нет
class GameError extends Errorсвой тип ошибки — тоже наследование!
this.name = 'GameError'имя, которое увидим в e.name
throw — «я не могу работать с такими данными». Кто вызвал функцию — тот ловит. finally — уборка, которая нужна всегда (закрыть файл, спрятать «загрузку»). Свой класс ошибки наследуется от Error — то же extends и super, что у героев.
